# アクションドライブ LED デバッグ手順書（4ピン構成版）

## 概要
アクションドライブ（Motor1/Motor2）のファームウェアをLEDで動作確認するための手順書です。
**ファームウェアコードは一切変更せず**、モーターの代わりにLEDを接続してデジタルON/OFF制御の動作を確認します。

**MQTT版と同一のピン配置・制御ロジック**を使用しています。

---

## 必要な部品

### 基本構成（1台分）
- ESP32開発ボード × 1台
- LED × 4個（赤/青/緑/黄など色分け推奨）
- 抵抗 220Ω～330Ω × 4個（LEDの電流制限用）
- ブレッドボード × 1個
- ジャンパーワイヤー 適量

### 2台構成（Motor1 + Motor2）
- ESP32開発ボード × 2台
- LED × 8個
- 抵抗 220Ω～330Ω × 8個
- ブレッドボード × 2個
- ジャンパーワイヤー 適量

---

## ピン配置（MQTT版と同一）

両方のファームウェアで共通:

| ESP32 GPIO | ESP8266相当 | 機能 | LED色（推奨） |
|------------|-------------|------|---------------|
| **GPIO 14** | D5 | 振動 強 (STRONG) | 赤 |
| **GPIO 12** | D6 | 振動 中強 (MEDIUM_STRONG) | オレンジ |
| **GPIO 13** | D7 | 振動 中弱 (MEDIUM_WEAK) | 黄 |
| **GPIO 15** | D8 | 振動 弱 (WEAK) | 緑 |
| GPIO 2 | - | オンボードLED（状態表示） | - |


### 詳細配線手順

1. **ESP32のGNDをブレッドボードのGNDレールに接続**
2. 各GPIOピンについて:
   - GPIOピンをブレッドボードの任意の列に接続
   - 同じ列にLEDのアノード（長い脚、+側）を挿入
   - LEDのカソード（短い脚、-側）から抵抗（330Ω）を経由
   - 抵抗の反対側をGNDレールに接続

### 推奨LED色と意味
| GPIO | LED色 | モード | 意味 |
|------|-------|--------|------|
| 14 | 赤 | STRONG | 最強振動 - 全LED点灯時に使用 |
| 12 | オレンジ | MEDIUM_STRONG | 中強振動 - D6+D7点灯時に使用 |
| 13 | 黄 | MEDIUM_WEAK | 中弱振動 - 単独で使用 |
| 15 | 緑 | WEAK | 弱振動 - 単独で使用 |

⚠️ **極性注意**: LEDは極性があります。逆接続すると光りません。
- **アノード（+）**: 長い脚
- **カソード（-）**: 短い脚

## 動作モード別のLED挙動

### 基本モード

| モード | D5(GPIO18) | D6(GPIO17) | D7(GPIO16) | D8(GPIO15) | 説明 |
|--------|------------|------------|------------|------------|------|
| `OFF` | ⚫ OFF | ⚫ OFF | ⚫ OFF | ⚫ OFF | 全消灯 |
| `WEAK` | ⚫ OFF | ⚫ OFF | ⚫ OFF | 🟢 ON | D8のみ点灯 |
| `MEDIUM_WEAK` | ⚫ OFF | ⚫ OFF | 🟡 ON | ⚫ OFF | D7のみ点灯 |
| `MEDIUM_STRONG` | ⚫ OFF | 🟠 ON | 🟡 ON | ⚫ OFF | D6+D7点灯 |
| `STRONG` | 🔴 ON | 🟠 ON | 🟡 ON | 🟢 ON | 全LED点灯 |

### パターンモード

| モード | パターン | タイミング |
|--------|----------|------------|
| `HEARTBEAT` | D7(ドッ)→OFF→D5(クン)→OFF→... | 1.5秒待機→D7(200ms)→OFF(100ms)→D5(150ms)→OFF |
| `RUMBLE_FAST` | 全LED点滅（速） | ON(150ms)→OFF(100ms)→ループ |
| `RUMBLE_SLOW` | 全LED点滅（遅） | ON(300ms)→OFF(300ms)→ループ |

## テスト手順

### 1. ハードウェア準備
1. ESP32に4つのLED+抵抗を配線（上記配線図参照）
2. USB経由でPCに接続
3. シリアルモニターを開く（115200 bps）

### 2. ファームウェア書き込み
```powershell
# Motor1の書き込み
cd c:\Users\kumes\StudioProjects\4d-at-home-android\esp32\action_drive_motor1
pio run --target upload

# Motor2の書き込み
cd c:\Users\kumes\StudioProjects\4d-at-home-android\esp32\action_drive_motor2
pio run --target upload
```

### 3. 起動確認
- シリアルモニターに以下が表示されることを確認:
```
4D@HOME ActionDrive Motor1 starting...
MQTT compatible - 4-pin digital control
Device name: 4D_AD1_XXXX
Pins: D5=14, D6=12, D7=13, D8=15
BLE advertising started
```
- オンボードLED（GPIO 2）が3回点滅

### 4. BLE接続確認
- スマートフォンやBLEツールで検索
- デバイス名: `4D_AD1_XXXX`（Motor1）、`4D_AD2_XXXX`（Motor2）
- UUIDでサービスを確認: `4D580001-0000-1000-8000-00805F9B34FB`

### 5. コマンド送信テスト

**COMMAND特性** (`4D580002-0000-1000-8000-00805F9B34FB`) に文字列を送信:

#### 基本動作確認
```
1. "MOTOR,WEAK"          → GPIO 15 (緑LED)のみ点灯
2. "MOTOR,MEDIUM_WEAK"   → GPIO 13 (黄LED)のみ点灯
3. "MOTOR,MEDIUM_STRONG" → GPIO 12 + 13 (オレンジ+黄LED)点灯
4. "MOTOR,STRONG"        → 全LED点灯
5. "MOTOR,OFF"           → 全LED消灯
```

#### パターン動作確認
```
1. "MOTOR,HEARTBEAT"   → 心拍パターン（黄→赤の点滅ループ）
2. "MOTOR,RUMBLE_FAST" → 全LED高速点滅
3. "MOTOR,RUMBLE_SLOW" → 全LED低速点滅
4. "MOTOR,OFF"         → 停止
```

### 6. 確認ポイント

#### ✅ 正常動作の兆候
- BLE接続が確立される
- コマンド送信後、対応するLEDが点灯/消灯
- シリアルモニターにログが出力される:
  ```
  Motor1 received: MOTOR,STRONG
  Motor1 mode set: STRONG
  ```
- モードに応じて正しいLEDの組み合わせが点灯
- パターンモードで正確なタイミングで点滅

#### ❌ 異常動作の兆候
- BLEデバイスが見つからない → ESP32の電源/初期化問題
- コマンド送信してもLEDが反応しない → 配線ミス or ファームウェア問題
- 1つのLEDしか光らない → 他のGPIO配線を確認
- パターンのタイミングがおかしい → loop()処理確認

## トラブルシューティング

### LEDが全く光らない
- **原因1**: LED極性が逆
  - **対処**: LEDを180度回転させて再接続
- **原因2**: 配線の接続不良
  - **対処**: ジャンパーワイヤーとブレッドボードの接続を確認
- **原因3**: GPIOピンが壊れている
  - **対処**: マルチメーターで電圧確認

### 一部のLEDしか光らない
- **配線ミス**
  - **対処**: 点灯しないLEDのGPIO配線を確認
  - GPIO 14, 12, 13, 15 が正しく接続されているか確認

### BLE接続できない
- **原因1**: ファームウェアが書き込まれていない
  - **対処**: `pio run --target upload` を再実行
- **原因2**: BLEの初期化失敗
  - **対処**: ESP32をリセット、シリアルモニターでエラー確認

### パターンが正しく動かない
- **原因**: loop()の処理遅延
  - **対処**: delay()が10ms以下になっているか確認
  - シリアル出力が多すぎると遅延することがある

## 実機モーター移行

LEDでの動作確認が完了したら、実機モーターへの移行は簡単です。

### 移行手順
1. ESP32の電源をOFF
2. **各GPIOからLED+抵抗を取り外す**
3. **各GPIOにモータードライバーの入力を接続**
4. モータードライバーの出力に振動モーターを接続
5. 電源を入れて同じBLEコマンドでテスト

### GPIO→モーター対応
```
GPIO 14 → モータードライバー1 → モーター1（強用）
GPIO 12 → モータードライバー2 → モーター2（中強用）
GPIO 13 → モータードライバー3 → モーター3（中弱用）
GPIO 15 → モータードライバー4 → モーター4（弱用）
```

### 注意点
- モーターは大電流を消費するため、ESP32のピンから直接駆動しない
- モータードライバー（トランジスタ、MOSFET等）を使用
- モーター用の独立電源を用意

## MQTT版との互換性

この構成はMQTT版（ESP8266）と**完全互換**です。

### 共通点
- ✅ ピン配置: GPIO 14, 12, 13, 15
- ✅ 制御方式: デジタルON/OFF
- ✅ モード名: STRONG, MEDIUM_STRONG, MEDIUM_WEAK, WEAK
- ✅ パターン: HEARTBEAT, RUMBLE_FAST, RUMBLE_SLOW
- ✅ 制御ロジック: 完全同一

### 相違点
- 通信: MQTT → BLE
- MCU: ESP8266 → ESP32
