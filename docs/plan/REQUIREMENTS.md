# 4D@HOME Androidアプリ 要件定義書 (Modern Android / Landscape)

## 1. デザインコンセプト & 世界観
* **テーマ**: **「Pocket Theater / Dark Immersion」**
    * 映画館の暗闇を想起させる**完全なダークモード**をベースとする。
    * 没入感を阻害しない「黒」を基調に、ブランドカラーの「赤」をアクセント（発光表現）に使用する。
* **スタイリング**:
    * **Material Design 3**をベースにしつつ、ゲーミング/エンタメ要素（ネオン感、透過ブラー）を取り入れる。
    * 角丸は少し大きめ（Rounded-lg / 12dp〜16dp）を採用し、親しみやすさとモダンさを両立。

## 3. 全体アーキテクチャ & 技術スタック
「今どきのAndroid開発」の標準に準拠し、宣言的UIとリアクティブなデータフローを採用します。

* **UIフレームワーク**: **Jetpack Compose** (Material Design 3)
* **ナビゲーション**: **Navigation Compose**
    * 横画面レイアウトに最適化するため、画面下部のBottomNavigationではなく、画面左端に配置する **Navigation Rail** を採用し、画面の縦幅を有効活用する。
* **アーキテクチャ**: **MVVM (Model-View-ViewModel) + Clean Architecture**
* **非同期処理**: **Kotlin Coroutines & Flow** (BLE通信、動画再生時間の監視に使用)
* **動画プレイヤー**: **Media3 (ExoPlayer)**
* **DI (依存注入)**: **Hilt**

## 4. 画面レイアウト共通仕様 (Landscape Mode)
* **画面オリエンテーション**: 横画面 (`SENSOR_LANDSCAPE`) 固定。
* **ナビゲーション (Navigation Rail)**:
    * 画面左端に常時表示される細いメニューバー。
    * アイコン構成:
        1.  **再生 (Playback)**: [Play Arrow Icon]
        2.  **制御 (Control)**: [Game Controller Icon]
        3.  **設定 (Settings)**: [Settings Icon]

## 5. 画面別詳細要件

### 5.1. 設定画面 (SettingsScreen)
BLEデバイスの管理と、エフェクトの割り当てを行うセットアップ画面です。横幅を活かし、左右2ペイン構成（左：スキャン/接続、右：マッピング設定）を推奨します。

#### **機能要件**
1.  **BLEスキャン制御**
    * **UI**: スキャン開始/停止のトグルスイッチ。
    * **状態表示**: スキャン中のプログレスインジケータ（円形）、Bluetooth権限（Permission）の未許可時の警告と権限リクエストボタン。
2.  **デバイス一覧表示**
    * **リスト項目**: デバイス名、MACアドレス、電波強度(RSSI)、接続状態アイコン。
    * **フィルタリング**: 「4D@HOME」または特定のUUIDを持つデバイスのみを表示するフィルタ機能（開発時は全表示トグルも用意）。
3.  **接続/切断処理**
    * **アクション**: リスト項目タップで接続/切断をトグル。
    * **フィードバック**: 接続成功時にToast表示および、行の背景色を強調（緑系など）。
4.  **エフェクト→デバイスマッピング**
    * **概念**: JSON内のエフェクトID（例: `wind`, `shock`）が、ハードウェア側のどのコマンド/ピンに対応するかを紐付ける。
    * **UI**:
        * エフェクト名（「風」「振動」「水」）ごとのカードを表示。
        * 各カード内にドロップダウンメニューを配置し、送信するコマンド（例: `CMD_01`, `CMD_02`）を選択可能にする。

### 5.2. 制御画面 (ControlScreen)
開発中のデバッグや、デモ展示時のオペレーター操作（「今ここで風を出したい」等）に特化した画面です。

#### **機能要件**
1.  **手動制御パネル (Manual Override)**
    * **レイアウト**: 画面左半分に大きく配置。
    * **UI**:
        * エフェクトごとの大型ボタン（Grid layout）。
        * ボタンを押している間だけ発動する「Momentaryモード」と、一度押すと一定時間発動する「Triggerモード」の切り替えスイッチ。
        * スライダーによる「強度（Intensity）」の調整（デバイス側が対応している場合）。
2.  **通信ログコンソール (Log Console)**
    * **レイアウト**: 画面右半分に黒背景のターミナル風UIを配置。
    * **表示内容**:
        * タイムスタンプ (`HH:mm:ss.SSS`)
        * 方向（`TX`送信 / `RX`受信）
        * コマンド内容（HexまたはASCII）
        * ステータス（Success / Fail）
    * **挙動**: 新しいログが追加されるたびに自動スクロール（Auto-scroll）。
3.  **ログ操作**
    * **UI**: コンソール右上に「ゴミ箱アイコン（Clear）」と「一時停止アイコン（Pause Log）」を配置。

### 5.3. 再生画面 (PlaybackScreen)
ユーザーが最も長く目にするメイン画面です。動画への没入感を最優先しつつ、デバッグ情報（同期状態など）を確認できるモードを備えます。

#### **機能要件**
1.  **動画プレイヤー**
    * **動画ソース**: アプリ内リソース（`res/raw` または `assets`）から動画ファイルを選択するドロワーメニューまたはダイアログ。
    * **プレイヤーUI**: ExoPlayerを使用。画面中央に大きく表示。再生/一時停止、シークバー、音量。
    * **没入モード**: 画面タップでNavigation Railやコントローラーを非表示にする機能。
2.  **JSONタイムライン同期エンジン**
    * **ロジック**: 動画の現在の再生位置（ミリ秒）を`Flow`で監視し、JSONデータのタイムスタンプと一致（または通過）した瞬間にBLEコマンドを発火。
    * **並列処理**: UIスレッドをブロックしないよう、コマンド送信はIOスレッドで行う。
3.  **\エフェクト表示 (Next Event HUD)**
    * **UI**: プレイヤー隅に半透明のオーバーレイを表示。
    * **視覚効果**: エフェクト発火の瞬間、オーバーレイが一瞬光るなどのビジュアルフィードバック（要件定義済みの色を使用）。
4.  **同期状態モニター**
    * **UI**: 画面隅に小さくステータスアイコンを表示。
        * 緑点灯: 正常同期中（BLE接続あり、ラグなし）。
        * 黄点滅: 遅延発生またはリトライ中。
        * 赤点灯: デバイス切断。
    * **機能**: 動画の一時停止時に、すべてのエフェクトを強制停止（All Offコマンド送信）する安全装置。
